# ربط فيسبوك — أخطاء حقيقية وحلولها

## رسالة: «لا توجد صفحة فيسبوك مرتبطة بهذا الرمز.»

لها **سببان مختلفان تمامًا**، وكانت الرسالة القديمة تخلط بينهما فتدفعك
للخطوات الخطأ.

| السبب | العلامة | الحل |
|---|---|---|
| **أ** الرمز لا يحمل `pages_show_list` | لا يستطيع قراءة الصلاحيات | أعد إنشاء الرمز مع الصلاحية |
| **ب** الصلاحية موجودة لكن لا صفحة مسندة | `/me/permissions` يُظهر الصلاحية | أسند الصفحة إلى مستخدم النظام |

### الإصلاح في الكود (v4-fb-diagnostics)

الدالة الآن تسأل `/me/permissions` أولًا وتقول السبب بالضبط:

```
الصلاحية pages_show_list موجودة، لكن لا صفحة مسندة لهذا الرمز.
أضف الصفحة: business.facebook.com ← مستخدمو النظام ←
إضافة أصول ← صفحات ← احتر صفحتك ← احفظ، ثم أنشئ رمزًا جديدًا.
```

وإن كانت الصلاحية غائبة، تعرض **الصلاحيات الموجودة فعلًا** حتى ترى الناقص.

> **قاعدة ذهبية:** الرمز لا يرى ما أُسند **بعده**. أي إسناد = رمز جديد إلزامي.

---

## إصلاح جذري ثانٍ: رمز الصفحة لا رمز المستخدم

الربط كان يحفظ رمز المستخدم، والعامل ينشر على `/{page_id}/photos` بذلك
الرمز. Facebook يقبل هذا أحيانًا عبر «التصرف بصفة الصفحة» — فينتج
**نجاح متقطع بلا سبب واضح**، وهو أسوأ من فشل صريح.

الآن:
1. الربط يقرأ `access_token` **الخاص بالصفحة** من `/me/accounts`.
2. يحفظه في `refresh_secret_id`.
3. العامل يستخدم `refresh_token || access_token` — أي رمز الصفحة أولًا.
4. يتحقق من `tasks` تحتوي `CREATE_CONTENT` قبل الحفظ.

---

## خطوات الإسناد (مرة واحدة)

1. `business.facebook.com/settings`
2. **المستخدمون ← مستخدمو النظام** ← اختر مستخدم النظام الذي أنشأ الرمز
3. **إضافة أصول** ← **صفحات** ← ضع علامة على صفحتك ← **حفظ**
4. ارجع لتوليد الرمز ← **أنشئ رمزًا جديدًا**
5. الصق الجديد في «ربط برمز»

## الأذونات المطلوبة في الرمز

```
pages_show_list      ← لقراءة الصفحة
pages_manage_posts   ← للنشر عليها (بدونها يُرفض النشر)
pages_read_engagement
```

## بعد الربط

صفحة فيسبوك تنشر الصور والفيديو. الفيديو يحتاج `file_url` عامًّا/موقَّعًا —
والعامل يوقّعه تلقائيًا.
