# تيك توك — ما يعمل وما لا يعمل، ولماذا

## الخلاصة في سطر

**تيك توك لا ينشر علنًا عبر API قبل تدقيق التطبيق.** هذا قيد من TikTok لا من الكود.
الطريق الذي يعمل اليوم: **«نسخ إلى TikTok Studio»** في جدول المنشورات.

## القيود الثلاثة (من وثائق TikTok)

### ١. تطبيق غير مدقَّق ⇒ منشور خاص دائمًا
> «All content posted by unaudited clients will be restricted to private viewing mode.»

الكود ينجح، والتطبيق يُعيد `200`، والمنشور موجود — **لكن لا أحد يراه غيرك**.
هذا أخطر ما في الأمر: يبدو ناجحًا وهو ليس كذلك.

### ٢. الحساب يجب أن يكون خاصًّا وقت النشر
إن كان الحساب عامًّا يجيب TikTok بـ:

```
unaudited_client_can_only_post_to_private_accounts
```

### ٣. `PULL_FROM_URL` يحتاج دومينًا موثَّقًا
تخزيننا على نطاق Supabase مولَّد، ولا يمكن إثبات ملكيته لـTikTok قبل ربط نطاق مخصص.

## ما أصلحه الكود (كانت أخطاء حقيقية)

| الخطأ السابق | الأثر | الإصلاح |
|---|---|---|
| `privacy_level: 'PUBLIC_TO_EVERYONE'` ثابتًا | **كل** محاولة تفشل | نسأل `creator_info` عن المسموح ونختاره |
| إعلان النجاح بعد `init` | ادعاء نشر لم يحدث | ننتظر `PUBLISH_COMPLETE` |
| تجاهل `FAILED` | مهمة «ناجحة» وهي فاشلة | خطأ حقيقي + سبب TikTok |
| إخفاء الخصوصية | المستخدم يظن المنشور عامًّا | ملاحظة صريحة تظهر في الواجهة |

## ماذا يحدث الآن إن ضغطت «انشر الآن» مع تيك توك

- **تنبيه قبل الحفظ** يشرح القيد ويشير إلى البديل.
- إن كان الحساب عامًّا ⇒ رسالة عربية: «اجعل حسابك خاصًّا مؤقتًا».
- إن كان الدومين غير موثَّق ⇒ رسالة عربية: «استخدم النسخ إلى TikTok Studio».
- إن نُشر فعلًا وهو غير مدقَّق ⇒ تُعرض: **«نشر بخصوصية أنا فقط. لا أحد غيرك يراه.»**

## الطريقان

| | «نسخ إلى TikTok Studio» | عبر API |
|---|---|---|
| يعمل الآن | ✅ | ❌ |
| يحتاج تدقيقًا | لا | نعم |
| نشر علني | ✅ (أنت تنشر) | بعد التدقيق فقط |
| يحتاج توثيق دومين | لا | نعم |
| الخطوات | نقرة واحدة | تطبيق ← دور مطوّر ← نطاق ← توثيق ← تدقيق |

**التوصية:** استخدم النسخ الآن، وأجّل التدقيق حتى تصبح تيك توك ضرورة.
