# استوديو بصمة إبداع

واجهة ثابتة لاستخدام Supabase Auth وقاعدة البيانات والتخزين الخاص في مشروع Imprint Studio. الكود لا يتضمن مفتاح service_role؛ مفتاح Supabase القابل للنشر موجود بالواجهة ويجب حماية البيانات بسياسات RLS.

## النشر عبر GitHub Pages
1. أنشئ مستودعًا جديدًا في GitHub وارفع محتويات هذا المجلد إلى جذر المستودع، بما فيها `.github/workflows/deploy.yml`.
2. في إعدادات المستودع، Pages ← Build and deployment ← Source اختر GitHub Actions.
3. ادفع الملفات إلى فرع `main` أو شغّل Workflow باسم Deploy Imprint Studio من تبويب Actions. عند اكتماله يظهر رابط الموقع في Settings ← Pages.
4. من لوحة Supabase مشروع Imprint Studio ← Authentication ← Users أنشئ المستخدم الوحيد بالبريد وكلمة مرور تختارها في لوحة التحكم، مع تأكيد بريده حسب إعدادات Supabase. لا تضع كلمة المرور أو مفاتيح service_role في GitHub.
5. عند استخدام روابط الدعوات أو إعادة تعيين كلمة المرور مستقبلًا، اضبط Site URL و Redirect URLs في Supabase على رابط GitHub Pages الصحيح؛ رابط الموقع الافتراضي الآن localhost وغير مناسب لها.

قد تتوقف إمكانية نشر مستودع خاص على نوع خطة GitHub؛ تحقق من إعدادات حسابك. محتويات GitHub Pages عامة حتى لو كانت بيانات Supabase خاصة. لا ترفع ملفات حساسة. لا تحوّل الموقع إلى عام قبل اختبار تسجيل الدخول والتخزين وسياسات RLS من حسابين، وتغيير كلمة مرور قاعدة البيانات وتدوير المفاتيح الإدارية التي ظهرت أثناء الإعداد.

## الوضع الحالي
يمكن تسجيل الدخول للمستخدم الذي يتم إنشاؤه في Supabase وحفظ/فتح مسودات مع ملفات ضمن الحدود والصيغ التي تتيحها مساحة التخزين. تحتاج تجربة دخول فعلية لاختبارها نهائيًا. الحسابات الاجتماعية والنشر والجدولة التلقائية غير مفعلة؛ اختيار وقت في المسودة لا ينشر تلقائيًا. لا يوجد تحليل AI. الربط والنشر يتطلبان خدمات خلفية آمنة وتطبيقات مطور لدى المنصات، ولا يمكن تنفيذها بمجرد GitHub Pages. هذه نسخة قيد التطوير وليست جاهزة للإطلاق العام.
